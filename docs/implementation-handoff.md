# 仕様・実装の申し送り

実装後に合意した変更を含め、次回の改修で維持する仕様と、それを確認する場所をまとめる。作業環境の準備とリリースは [開発手順](development.md) を参照。

## システム構成と保存

- ASP.NET Core MVCのサーバー描画とJavaScriptで構成する。認証はASP.NET Core Identity、保存はEF CoreとSQLite。ブラウザではPC・スマホ幅で同じ機能にアクセスできるようにする。
- 暦日と繰り返しはサーバーのタイムゾーンで扱う。日記・期限・繰り返しの元の日付は暦日として保持し、監査・通知・更新などの時刻はUTCで保存する。
- アプリは1つのデータディレクトリを1プロセスで使用する。DBはWALモードで、起動時に移行する。SQLite、画像とData Protectionの鍵、Web Pushの鍵は永続領域で管理する。同じ保存先の多重起動は排他ロックで拒否する。
- 初回リリース用DBは、開発途中の履歴を統合した初期マイグレーションから作る。プレリリースより前の開発用DBや旧形式のZIPに変換処理は用意していない。配布後に構造を変えるときは、移行と既存ファイルの互換性を個別に扱う。
- 本番はHTTPSのルートURLを設定する。`KnownProxies` は指定したプロキシからの転送情報を受け入れ、`DeploymentManaged` は配置で接続経路を限定したうえでHTTPS情報だけを使う。ヘルスチェックはコンテナ内のループバックから、DB接続・未適用マイグレーション・ファイルログの状態を確認する。
- 運用ログは標準出力とJSON Linesファイルで扱う。ファイルログはUTC日付で管理し、50MBで分割して当日を含む30日分を保持する。認証・管理操作の監査記録は別に90日保持する。ログ処理へ本文、認証情報、画像、通知購読URLを追加しない。

参照先は [Program](../src/Hibitsuzuri.Web/Program.cs)、[保存先](../src/Hibitsuzuri.Web/Storage/DataDirectory.cs)、[DB初期化](../src/Hibitsuzuri.Web/Storage/DatabaseInitializer.cs)、[運用ログ](../src/Hibitsuzuri.Web/Hosting/OperationalLogging.cs)。

## 認証とアカウント

- 初回登録の完了判定はユーザー数ではなく `AccountPolicy.SetupCompleted`。起動時、未完了なら256ビットの初回登録コードをデータ領域の `setup-token.txt` に保存する。コードは64桁の16進数、有効期限は24時間。期限内は再起動しても同じ値を保持し、期限切れは起動時に再発行する。
- Linuxのファイル権限は `0600`。不正な権限やリンク、破損は起動時に検出する。登録失敗ではコードを消費せず、DBの確定後に失効・削除する。削除に失敗しても完了済みの状態では再登録できない。
- 日記帳・日記・画像・タスク・記念日は所有者単位。管理者が他人の記録を閲覧する機能は設けていない。追加ユーザーの登録受付は管理者が制御する。最後の有効な管理者を解除・停止・削除できないようにする。
- パスワードとパスキーでログインできる。パスキーの管理操作は必要に応じて再認証する。認証器が応答JSONに拡張結果を含めない場合も、WebAuthn APIから取得できる結果または空オブジェクトを補って送る。提供元の表示名は同梱の対応表から取得し、更新用Actionsが差分をPRにする。
- リカバリーコードはパスワードを再設定するための一度限りのコード。10件発行し、ハッシュだけを保存する。復旧では旧コード・旧パスキー・既存のセッションと通知購読を失効させ、新しいコードの保存確認を求める。
- セッションの期限は通常8時間、ログイン状態を保持する場合は30日。期限切れ・失効済みのセッションは定期処理で回収する。自然な期限切れではWeb Pushを継続し、明示ログアウトではそのブラウザの通知を停止する。

参照先は [SetupToken](../src/Hibitsuzuri.Web/Auth/SetupToken.cs)、[SessionService](../src/Hibitsuzuri.Web/Auth/SessionService.cs)、[AccountRecoveryService](../src/Hibitsuzuri.Web/Auth/AccountRecoveryService.cs)、[Passkey提供元の更新](../.github/workflows/update-passkey-providers.yml)。

## 日記帳・日記・画像

- 基本画面は閲覧用で、編集は別画面。閲覧中の日付が過去でも日記は編集できるため、日付による操作制限の説明はタスク欄に置く。利用中の日記帳は選択欄で切り替え、アーカイブは管理画面から開く。
- 同じ日記帳・日付の日記は1件。ゴミ箱でも日付を占有する。通常の新規作成は未来日を対象にしない。テンプレートを適用するのは新規本文を開くとき。日記本文は10万文字までで、現行版とは別に過去5版を保持する。編集履歴から読み込んだ本文は、明示保存して現行版にする。
- 下書き本文はブラウザに保存する。ユーザー・日記帳・日付・タブを分け、下書き候補は利用者が選ぶ。保存時は版を照合して競合を検知し、最新版との比較を案内する。同じ操作IDの再送は二重保存しない。
- 画像は所有者の権限を確認して配信する。Markdownの画像参照は `attachment:<ID>`。代替テキストは画像の `alt` に使う。本文、履歴、テンプレート、有効な下書きからの参照を考慮して実体を保持し、下書きだけの画像は保持期限を30日にする。切り貼りで参照が一時的に消えても、保持期限内なら再挿入できる。
- 「本文から外す」と「画像の削除」は別の操作。明示的な完全削除では履歴等の参照を残したまま画像実体を削除できる。後でその版を開いたときは欠落表示にする。
- 画像取り込みはJPEG・PNG・WebP・GIFで1枚20MiBまで。既定では静止画像の向きを補正し、長辺が2560pxを超える場合は縮小・非可逆WebP、それ以下は可逆WebPで保存する。変換時には位置情報等を引き継がない。アニメーションや利用者が元画像を保持する設定にした場合は、検証のうえ原本を保存する。

参照先は [DiaryController](../src/Hibitsuzuri.Web/Controllers/DiaryController.cs)、[DiaryMarkdown](../src/Hibitsuzuri.Web/Diary/DiaryMarkdown.cs)、[編集画面の処理](../src/Hibitsuzuri.Web/wwwroot/js/diary-editor.js)、[ImageStore](../src/Hibitsuzuri.Web/Images/ImageStore.cs)、[ImageConverter](../src/Hibitsuzuri.Web/Images/ImageConverter.cs)。

## タスク・祝日・記念日

- 未完了一覧と完了一覧を分ける。期日なしも扱い、完了履歴は初期表示を絞り、「さらに表示」で続きが読める。過去の日付の日記画面ではタスクを閲覧専用とし、操作はタスク一覧から行う。
- 日・週・月・年の繰り返しと休日調整を扱う。「今回以降」の変更は新しい区間に分け、完了済みや個別編集済みの回は旧区間の記録を保持する。「今回のみ」の削除はその回のスキップとして記録する。「今回以降」の削除は、その範囲の未操作回を取り消す。
- 停止期間は未操作の回をスキップし、再開日から予定を生成する。到来・操作済みの回と通知時刻が到来した回は固定し、祝日データの変更で履歴を動かさない。必要な範囲だけ予定を計算し、再計算できる予定の索引は記録と区別する。
- 日本の祝日は確認済みデータを同梱し、空のDBを初期化する。公式データの取得先は公開データカタログから解決し、1日1回を上限に自動確認する。管理者は手動更新できる。失敗時は既存データを保持し、取得できていない期間を区別する。出典・規約・加工の説明はアプリ内のライセンス画面に掲載する。
- 記念日は全日記帳または個別の日記帳へ表示できる。2月29日の扱いは非うるう年に表示しない、2月28日、3月1日から選ぶ。

参照先は [TasksController](../src/Hibitsuzuri.Web/Controllers/TasksController.cs)、[RepeatRule](../src/Hibitsuzuri.Web/Tasks/RepeatRule.cs)、[TaskSchedule](../src/Hibitsuzuri.Web/Tasks/TaskSchedule.cs)、[HolidayUpdates](../src/Hibitsuzuri.Web/Calendar/HolidayUpdates.cs)、[データ出典の表示](../src/Hibitsuzuri.Web/Views/Holidays/About.cshtml)。

## 通知とPWA

- リマインダーは1タスクにつき最大3件。期限からの相対指定と日時指定を扱い、繰り返し系列の設定は相対指定を使う。有効な端末へ配信し、タスク名は既定で隠す。端末ごとに表示を許可できる。メモは通知に含めない。
- 遅延通知の再試行は予定時刻から1時間以内。Web Pushの有効期限は予定時刻を起点に3時間。送信の重複を配信記録で抑え、受信側では表示前にサーバーへ許可を照会する。配信先サービスでの受け付けと、端末での表示は別々に確認する。
- PWAはホーム画面への追加とアプリとしての起動に対応する。Service Workerのキャッシュは接続失敗時の案内などの公開資材に限定する。認証済み画面、本文、画像、API応答はオフライン閲覧用に保持しない。
- 編集中の切断では入力欄と下書きを保持する。接続復帰で勝手に保存や再送を行わず、利用者が保存操作を行う。

参照先は [Reminders](../src/Hibitsuzuri.Web/Notifications/Reminders.cs)、[PushDispatcher](../src/Hibitsuzuri.Web/Notifications/PushDispatcher.cs)、[Service Worker](../src/Hibitsuzuri.Web/wwwroot/sw.js)。

## バックアップと復元

| 機能 | 維持する仕様 |
| --- | --- |
| 個人バックアップ | 日記帳、本文、過去5版の履歴、テンプレート、タスク・固定済み予定・リマインダー、記念日を対象とする。アーカイブを含み、ゴミ箱・認証情報・通知端末・ブラウザの下書きは対象外。DBモデルを直接シリアライズせず、専用のレコードを使う。 |
| 画像の選択 | 個人バックアップとMarkdownの両方で画像あり／なしを選べる。画像を外しても本文内の参照を保持する。個人バックアップの復元では、同じIDが現在の環境にあっても画像を再接続しない。 |
| 追加復元 | 既存の記録を維持し、同名の日記帳は `-2` などで区別する。全日記帳指定の記念日は今回追加した日記帳だけへの個別指定に変換する。 |
| 置き換え復元 | 所有者のゴミ箱を含む記録全体を置き換える。アカウント、認証情報、個人設定、通知端末は維持する。画像なしのZIPでは既存の画像も置き換え対象になる。 |
| 復元後の通知 | 復元したタスクは停止設定を維持し、復元完了後の通知予定を既に有効な端末へ配信する。追加復元前からあるタスクの通知も継続する。 |
| Markdown取り込み | アプリから書き出したZIPが対象。構成情報・日記帳フォルダー・日付付きファイル名・日付ヘッダーを維持したまま本文を編集できる。日記帳ごとに既存または新規の取り込み先を選ぶ。同日の本文を上書きして旧履歴を削除し、ZIPにない日付は維持する。 |
| Markdownの画像 | 同梱画像を検証して登録する。画像なしの場合は、同じアカウントに利用可能な元画像が残っていれば再利用する。利用できない参照は欠落として表示する。 |

ZIPは圧縮後2GB・展開後4GBまで。データと同じ領域の `transfers` に一時保存し、ZIPをOS上の任意パスに展開せず検証する。個人バックアップでは目録のチェックサムを確認する。検証後の確定期限は1時間。確認時点から復元先の記録が変わった場合は再確認を求める。確定はトランザクションで行い、DBの確定前に既存の画像ファイルを消さない。操作IDにより同じ復元を二重に適用しない。

参照先は [BackupArchive](../src/Hibitsuzuri.Web/Backups/BackupArchive.cs)、[RestorePlanning](../src/Hibitsuzuri.Web/Backups/RestorePlanning.cs)、[BackupRestore](../src/Hibitsuzuri.Web/Backups/BackupRestore.cs)、[MarkdownImport](../src/Hibitsuzuri.Web/Backups/MarkdownImport.cs)、[BackupTests](../tests/Hibitsuzuri.Tests/BackupTests.cs)。
